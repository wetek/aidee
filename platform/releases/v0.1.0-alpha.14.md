# Aidee v0.1.0 Alpha 14

## Purpose

Refresh Aidee-managed Hermes runtime context when controller or assistant
instructions change, and add resumable onboarding without deleting
conversation history or owner configuration.

## Hermes runtime context

- Controller and assistant runtimes still use Hermes `v2026.9.11`, source
  commit `939e45c91d751fadd94dcd1b873ac3cb44846213`.
- Aidee applies a temporary audited patch with SHA-256
  `168c5dbf386b8570764bb8730bc113d31f45c4cb76498a987bb1d1a09b934701`.
- The patch fingerprints the assembled system prompt, model, provider, working
  directory, and bounded digests of provider-visible tool definitions.
- Persisted sessions retain every message. A missing or changed fingerprint
  rebuilds and persists the prompt and tool list on the next turn.
- Unchanged runtime context keeps the persisted prompt bytes and cached agent.
- Gateway agent cache identity now includes resolved SOUL content and working
  directory. Existing tool registry and toolset inputs remain part of that
  identity.
- Prompt bytes, their fingerprint, and the persisted tool order use one
  database transaction, so concurrent refreshes cannot leave mixed metadata.

## Delivery and verification

Controller install and update apply the patch only to the pinned Hermes commit.
Assistant image builds apply the same patch to the pinned image source. Both
paths verify the patch checksum, base file checksums, and resulting file
checksums. Image labels and records contain the Hermes source commit and patch
checksum.

This patch is temporary. Remove it when Aidee moves to a Hermes release that
contains an equivalent tested fix.

## Resumable onboarding

- Controller and assistant onboarding now use one versioned state module with
  locked atomic updates, evidence-gated completion, explicit skip reasons, and
  deterministic required and optional rollups.
- Legacy `complete` and verified controller fields migrate to `completed`.
  Legacy `not_applicable` and `skipped` migrate to an explicit skip. Legacy
  `deferred` returns to `pending`.
- The gate offers resume once when a required step is incomplete. `Not now`
  records the answer and suppresses later offers until manual reopen or a
  schema adds a required step. It never schedules a reminder.
- Optional steps do not trigger the offer, but the resumed flow must complete
  or explicitly skip them before the rollup becomes complete.
- Coding and project assistants must resolve repository and coding-tool setup.
  Personal and client assistants may skip those steps with an owner-confirmed
  reason.
- The updater migrates the controller and every assistant, repairs assistant
  dashboard skin and branding, refreshes prompts and tools, updates registry
  rollups, and passes controller status to default cron reconciliation.
- External actions remain pending unless an owner confirmation or verified
  tool result proves them. Local reconciliation marks only the state it checks.
- Assistant images include the onboarding gate and mark commands under
  `/opt/aidee/onboarding`.

## Migration

No SQLite rewrite or message migration runs. Alpha 13 sessions have no runtime
context fingerprint, so their first turn after upgrade rebuilds the managed
prompt once and records the fingerprint in the existing session model metadata.
The fleet updater rebuilds and validates the assistant image, replaces
assistant containers while preserving bind-mounted state, and restarts the
controller gateway through normal service reconciliation.

The onboarding migration does not read secrets or modify Hermes `state.db`.
It preserves configuration, credentials, histories, memory, repositories, and
recorded owner choices. Migration `002_alpha14_onboarding_status` copies every
legacy controller and assistant onboarding document to a root-only backup
before desired-state reconciliation transforms it.

## Test status

The patched Hermes prompt-restore and agent-cache files pass their 70 focused
tests. The Aidee suite, repository validation, Python compilation, Bash syntax,
ShellCheck, and diff checks also pass.

The unrelated upstream Hermes FTS SQL trace baseline failure remains a known
full-suite issue. Do not treat that baseline as permission to hide any new
failure.

## Rollback

The rollback target is `v0.1.0-alpha.13`.

Rolling back the runtime does not remove session messages. Older Hermes code
ignores the added model metadata key. A rollback may reuse the prompt last
persisted by Alpha 14.
