# Aidee v0.1.0 Alpha 27

## Purpose

The controller dashboard and each assistant dashboard now open on Aidee-owned
home pages. The owner can see the fleet and each assistant, and configure
install-wide Langfuse plus OpenCode, without a second web app.

## Apply

- Controller `/` is Fleet overview: host, release, onboarding, and all
  assistants. Assistant cards are read-only. Open dashboard is the card
  action.
- Assistant `/` is Overview for that assistant only: identity, memories,
  and OpenCode. Tracing status there is read-only.
- One Langfuse project per Aidee install. Keys are entered once on the
  controller. Assistants inherit. Filter with `HERMES_LANGFUSE_ENV` /
  `LANGFUSE_ENVIRONMENT` (`controller` or the assistant id).
- A marked SOUL.md instruction tells the agent that this is Aidee agent
  tracing, not a repository's Langfuse.
- Keys live in that environment's Hermes `.env` (Custom Keys / Langfuse
  section). OpenCode also gets official `opencode.json` and
  `opencode-langfuse.json` under `$HOME/.config/opencode/`.
- Controller OpenCode enable runs npm install of the pinned package and
  restarts the gateway. Assistants keep the image CLI. Enable writes the
  skill plus a SOUL coding-delegation block and restarts the container.
- Langfuse setup follows the official Hermes and OpenCode docs:
  https://langfuse.com/integrations/other/hermes and
  https://langfuse.com/integrations/developer-tools/opencode
- Fleet tab still owns dashboard passwords.

## Migration

No new state migration. Re-run the fleet updater after this tag is active.
Existing hosts pick up the home plugins on apply. Enter Langfuse keys on
the controller if you want install tracing.

## Validation

- Unit tests cover fleet overview, assistant home, Langfuse inheritance,
  OpenCode enable, secret filtering, and plugin install.
- Repository validation and unit tests pass.

## Rollback

Roll back host and assistant image state to `v0.1.0-alpha.26`.
