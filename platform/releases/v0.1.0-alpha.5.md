# Aidee v0.1.0 Alpha 5

## Purpose

Let the controller provision isolated assistants from one shared local image.

## Shared image

- Official Hermes `v2026.9.11` image pinned by digest.
- GitHub CLI, jq, socat, and OpenCode 1.18.3.
- Versioned Aidee skills, instructions, workflows, and defaults.
- One immutable image ID reused across assistant containers.
- Root-owned validated image record under `/etc/aidee/images`.

## Administration helper

- Root-owned system service.
- Controller-only Unix socket.
- JSON Schema request validation.
- Fixed image build, create, start, stop, and status operations.
- No arbitrary Docker flags, paths, environment files, Compose files, or shell commands.
- Idempotent request records.

## Assistant isolation

- Separate container and Hermes data directory.
- Individual identity, config, and memory mounts.
- Read-only root filesystem.
- Bounded temporary filesystems.
- CPU, memory, and process limits.
- No Docker socket, host networking, or privileged mode.

## Provisioning

The controller interviews the owner in Telegram, shows a plan, waits for approval, and submits a validated request. The first canary is a personal assistant without repository access.

## Validation required

The first VPS test must prove:

- Shared image build and tool versions.
- Two containers use the same image ID.
- Assistant state remains isolated.
- Private Tailscale dashboard ports work.
- Removing or stopping one assistant does not affect another.
