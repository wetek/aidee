# Aidee v0.1.0 Alpha 18

## Purpose

Install the onboarding plugin where Hermes loads user plugins, copy a
recorded dashboard origin into assistant config, and move leftover git
clones out of Hermes home. Alpha 17 enabled the plugin in config only, so
greetings still skipped the offer. Telegram menu buttons also ignored a
recorded custom origin.

## Onboarding

- Reconcile copies `aidee-onboarding` into `/opt/data/plugins` and enables it
  in `config.yaml` and `profiles/default/config.yaml`.
- The plugin injects an offer until the owner answers, and a continue prompt
  after `Resume now` while required steps remain.
- `hermes plugins enable` uses `--no-allow-tool-override` so apply is not
  blocked by a hidden TTY prompt.

## Dashboard origin

- Tailscale remains the default published origin. A custom HTTPS hostname is
  optional and per dashboard.
- `set_dashboard_origin` writes `registry.yaml` `dashboard.url` and that
  assistant's `config.yaml` `dashboard.public_url`.
- Reconcile copies the registry URL into `config.yaml`. Assistants must set
  the Telegram menu button to `public_url`. They must not invent a Tailscale
  host.
- Telegram profile apply writes descriptions for the default language and
  `en`, and treats trailing slashes on menu URLs as the same origin.

## Legacy clones

- Git checkouts left in an assistant Hermes home, or one directory below it,
  move to `/opt/data/aidee/repos`. A name that already exists there is moved
  to `/opt/data/aidee/legacy-home-repos` instead of overwritten.

## Migration

`003_alpha18_relocate_home_repos` records the first relocate. Later applies
repeat the same move if a leftover clone appears again. Re-run the fleet
updater after this tag is active.

## Validation

- Unit tests cover plugin install, continue inject, published origin
  matching, language-specific Telegram descriptions, and leftover clone
  relocation.
- Repository validation and unit tests pass.

## Rollback

Roll back host and assistant image state to `v0.1.0-alpha.17`.
