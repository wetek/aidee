# Aidee v0.1.0 Alpha 16

## Purpose

Make incomplete onboarding interrupt a greeting. Alpha 15 left that to the
model reading SOUL. A new conversation that said hi never ran the gate.

## Onboarding enforcement

- Hermes plugin `aidee-onboarding` inspects the durable gate on every turn
  and, when the decision is `offer`, injects a mandatory clarify instruction
  into that turn's user message.
- Assistant images ship the plugin under `/opt/hermes/plugins`. Existing
  assistant `config.yaml` files gain `aidee-onboarding` in `plugins.enabled`
  without dropping other plugins.
- Controller install and knowledge sync enable the same plugin.
- SOUL and the controller-onboarding skill tell the model to run the gate
  before greeting.
- `--mode reopen` now returns `offer` when a required step is still
  incomplete, instead of printing `silent` after resetting the prompt.

## Host inspect

Assistant onboarding status may be inspected from the host path
`/var/lib/aidee/runtime/assistants/<id>/data/aidee/onboarding-status.json`
as well as from `/opt/data/aidee/onboarding-status.json` inside the
container.

## Migration

No new state migration. Re-run the fleet updater after this tag is active.
Existing required and optional leftovers stay pending until the owner
resumes or skips them.

## Validation

- Unit tests cover gate reopen, plugin injection, plugin enablement, and
  image/plugin install paths.
- Repository validation and unit tests pass.

## Rollback

Roll back host and assistant image state to `v0.1.0-alpha.15`.
